# Craft docs: Connect API end to end

Craft is Connect-API-only now, per product decision: the hosted MCP OAuth
stack is gone (mok-5tl), the docs section lists via one
`GET /documents?fetchMetadata=true` sorted last-modified first (mok-psz),
rows open the native app via the API's `clickableLink` deep link because
craft's web editor cannot render unauthenticated (mok-l3q — verified:
empty skeleton + 403, no sign-in redirect), and the preview pane shows a
quiet loading overlay until the guest's first dom-ready (mok-115). The
renderer never shows fixture rows behind a bridge on an RPC error — empty
section + one-line notice instead; that masquerade was the original bug
report.

Notion keeps its hosted MCP flow. Don't reintroduce MCP for Craft
(`bd recall craft-uses-connect-api`).

The connection URL is the credential (paste once, Craft → Settings → API);
sign-out clears both credential kinds including the MCP-era keychain
entries.

Dev capture: `MOKI_SCROLL_TO=<data-testid>` scrolls any below-the-fold
section into view for captures (new this session — the docs Craft section
needed it). Captures of the current state: /tmp/mok-docs2-*.png.

mok-d5k (out-of-order RPC responses): both positional matcher twins
(Google + Notion `fixturesRegistrationAnswersUnavailable`) now match by
request id, so the gate stops coin-flipping. Root cause — RPCServer
answers each line in its own task, responses can arrive out of order —
is still open on the bead; consider ordered dispatch or auditing any
other positional matchers.

The app is relaunched and left open on the new build.
